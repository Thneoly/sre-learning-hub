# 写作风格契约（所有内容生成必须遵守）

本目录是一套面向**有网络/运维背景、正在备考 CKA / CKS / PCA 的工程师**的学习中心。
读者已在 VMware 里有一套 kubeadm 练习集群（base VM `172.30.30.21`，可 `ssh cka0000XX` 到各节点）。

## 通用规则

1. **语言**：简体中文正文，技术名词、命令、字段名保留英文原文。
2. **禁止**：成堆 emoji、空话套话、"大家好"式开场、未填写的占位符（TODO / 待补充 / XXX）。
3. **正确性高于一切**：所有 YAML / bash / PromQL 必须语法正确、可直接执行。不确定的版本细节就标注"以官方文档为准"，不要编造。
4. **图**：用 ASCII 字符画（代码块内），不用 mermaid（本地 Markdown 查看器不一定渲染）。
5. **链接**：延伸阅读只给官方或权威链接（kubernetes.io、prometheus.io、github 官方仓库）。
6. **文件名**：全部 ASCII；内容里标题用中文。
7. **命令块**：标注运行位置，格式为代码块第一行注释 `# [master]`、`# [worker1]`、`# [任意节点]`、`# [本地Windows]`。

## 章节文件模板（教程类，目标 250~450 行）

```markdown
# NN · 中文标题

> 模块：xxx ｜ 建议时长：x 小时 ｜ 关联认证：CKA-存储 / PCA-PromQL / —（无直接考点）

## 学习目标
- 3~5 条，用"能解释/能操作/能排查"开头的可验证句式

## 1. 正文分节
   原理讲解：为什么这样设计 → 机制怎么运转 → 关键对象/字段
   每个重要机制配 ASCII 图或表格

## 实战演练
   在练习集群上动手的完整步骤（命令 + 预期输出 + 验证方法）

## 常见坑
   表格：症状 | 原因 | 解法

## 自测
   5 个左右深挖问题（不是名词解释，是"为什么/如果……会怎样"）
   每题答案用 <details><summary>答案</summary>……</details> 折叠

## 延伸阅读
- 官方文档链接
```

## Lab 文件模板（练习类，每个 lab 一个目录，含 3 个文件）

`NN-slug/task.md`：
```markdown
# Lab NN · 标题
> 难度：★☆☆~★★★ ｜ 考点：CKA-网络 ｜ 前置：lab XX 或"无" ｜ 预计 20~40 分钟

## 场景
一段真实的运维情境描述（像考题一样给上下文，不提示解法）

## 任务清单
1. …（编号列出，每条一个可验收的动作）

## 验收标准
- 明确的终态描述（kubectl 能看到什么、curl 通不通）

## 提示（卡住再看）
<details><summary>提示 1</summary>…</details>
```

`NN-slug/check.sh`：bash 判分脚本，Ubuntu 上运行。要求：
- 开头 `#!/usr/bin/env bash` + `set -u`
- 内嵌 helper（pass/fail 函数与计分），**不依赖本仓库其他文件**，可单独拷到机器上跑
- 只读检查（kubectl get/deserve/jsonpath 查询比对），不修改集群
- 结束输出 `SCORE: X/Y` 和逐项 PASS/FAIL；全部通过 exit 0
- 对环境有假设处（如需要某 deployment 存在）在开头注释说明

`NN-slug/solution.md`：逐步讲解——每步"做什么 + 为什么 + 验证输出"，最后附 check.sh 的通过结果。

## 题库文件模板（Lab 三件套的豁免形态，仅限 08-pca）

PCA 的 PromQL / Alertmanager 考点以"查询与配置辨析"为主，练习的正确性依赖
Prometheus UI / `amtool` 的交互结果，无法用只读 bash 脚本逐题判分，因此
`08-pca/labs/` 允许采用**单文件题库**形态（如 `promql-exercises.md`、
`alertmanager-exercises.md`），不要求改造为 lab 目录三件套。题库文件必须满足：

- 一个主题一个文件，文件名 `<topic>-exercises.md`，题号连续（Q1…/A1…）并按组划分
- 开头有"如何验证你的答案"一节：给出练习集群 / 在线 playground 两种验证方式
  （含命令与运行位置标注），alertmanager 类须给出 `amtool check-config` /
  `config routes test` 等只读校验手段
- 每题结构固定：场景 → 要求 → 预期输出 → 折叠答案（含"解析"与"常见错误"）
- 结尾有"收尾自查"（5 个左右深挖问题，答案折叠）与"延伸阅读"（官方链接）

其他模块（03-docker / 05-cka / 07-cks 等实操型）仍一律使用 lab 目录三件套，
不得套用题库形态。
